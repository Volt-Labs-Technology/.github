# Volt Labs Technology

We write software that helps large computing facilities use electricity when it is cheap and clean, and stay within the limits of their site.

## Public libraries

| Library | What it does | Who it is for | CI | Version | Docs |
| --- | --- | --- | --- | --- | --- |
| [modbus-read](https://github.com/Volt-Labs-Technology/modbus-read) | A read-only Modbus TCP client. Modbus TCP is a request/response protocol used by electricity meters and power-distribution units. The crate encodes a register read, decodes the reply, and cannot express a write. | An engineer with a meter or similar device on a TCP network who needs to read registers from Rust without taking a dependency that can write. | [![CI](https://github.com/Volt-Labs-Technology/modbus-read/actions/workflows/ci.yml/badge.svg?branch=main)](https://github.com/Volt-Labs-Technology/modbus-read/actions/workflows/ci.yml) | [![crates.io](https://img.shields.io/crates/v/modbus-read.svg)](https://crates.io/crates/modbus-read) | [docs.rs](https://docs.rs/modbus-read) |
| [energy-tariff](https://github.com/Volt-Labs-Technology/energy-tariff) | Types and calculations for a site's electricity contracts. The tariff is data; the crate computes each charge that is present. | Anyone who needs those contracts as typed values and per-charge ledgers in Rust, without opening files or talking to a utility. | [![CI](https://github.com/Volt-Labs-Technology/energy-tariff/actions/workflows/ci.yml/badge.svg?branch=main)](https://github.com/Volt-Labs-Technology/energy-tariff/actions/workflows/ci.yml) | [![crates.io](https://img.shields.io/crates/v/energy-tariff.svg)](https://crates.io/crates/energy-tariff) | [docs.rs](https://docs.rs/energy-tariff) |
| [interval-align](https://github.com/Volt-Labs-Technology/interval-align) | Turns irregular time-stamped samples into fixed-length interval readings. Gaps are reported, never filled in. | Rust programs that ingest metering or monitoring feeds at irregular rates and need to summarise them over fixed intervals without inventing data. | [![CI](https://github.com/Volt-Labs-Technology/interval-align/actions/workflows/ci.yml/badge.svg?branch=main)](https://github.com/Volt-Labs-Technology/interval-align/actions/workflows/ci.yml) | [![crates.io](https://img.shields.io/crates/v/interval-align.svg)](https://crates.io/crates/interval-align) | [docs.rs](https://docs.rs/interval-align) |
| [sacct-parse](https://github.com/Volt-Labs-Technology/sacct-parse) | A parser for one row of Slurm's `sacct` accounting export. Slurm is a job scheduler used on many computing clusters; `sacct` is its accounting command. Each rejected field is named. | A cluster administrator or tooling author who has that export and wants typed records, without taking on anyone's scheduling opinions. | [![CI](https://github.com/Volt-Labs-Technology/sacct-parse/actions/workflows/ci.yml/badge.svg?branch=main)](https://github.com/Volt-Labs-Technology/sacct-parse/actions/workflows/ci.yml) | [![crates.io](https://img.shields.io/crates/v/sacct-parse.svg)](https://crates.io/crates/sacct-parse) | [docs.rs](https://docs.rs/sacct-parse) |
| [export-bundle](https://github.com/Volt-Labs-Technology/export-bundle) | Copies data files while keeping only an allow-list of columns, refuses files whose headers name people or machines, and writes a manifest with hashes and row counts so the bundle can be checked later. | Anyone who has to hand files to someone else and wants a record of exactly which bytes left. | [![CI](https://github.com/Volt-Labs-Technology/export-bundle/actions/workflows/ci.yml/badge.svg?branch=main)](https://github.com/Volt-Labs-Technology/export-bundle/actions/workflows/ci.yml) | [![crates.io](https://img.shields.io/crates/v/export-bundle.svg)](https://crates.io/crates/export-bundle) | [docs.rs](https://docs.rs/export-bundle) |

## How we write open-source code

These are small, pure libraries published on [crates.io](https://crates.io) under the MIT licence. Every public function is documented and tested. Warnings are errors. Example data is synthetic and labelled as such. The API of each crate may change before 1.0.

## Contribute or report a vulnerability

The same two files live in every repository above. To contribute, follow [CONTRIBUTING.md](https://github.com/Volt-Labs-Technology/modbus-read/blob/main/CONTRIBUTING.md). To report a vulnerability, follow [SECURITY.md](https://github.com/Volt-Labs-Technology/modbus-read/blob/main/SECURITY.md).
